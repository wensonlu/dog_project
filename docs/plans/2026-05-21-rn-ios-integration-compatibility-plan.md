# RN 页面集成到 iOS App 兼容改造方案（汪星球领养）

## 1. 目标与范围

本文档用于指导将现有 RN（Expo）页面逐步集成到 iOS 原生 App 中，保证：

- 登录态一致
- 路由可互通
- UI 风格统一
- 性能与稳定性可控
- 支持灰度发布与快速回滚

当前优先范围：宠物详情页、论坛详情页（已存在 RN 重构试点）。

## 2. 三层改造总览

### 2.1 底层基建（必须）

1. Hybrid 容器
- 在 iOS App 中提供 RN 容器入口（可承载 Expo/RN Bundle）。
- 原生路由可跳转到 RN 页面。

2. JS-Native 通信桥
- 统一协议：`eventName + payload + requestId + timeout`。
- 约定错误码：鉴权失败、参数错误、网络异常、业务异常。

3. 统一路由协议
- Deep Link 统一为 `dogproject://`。
- 路由示例：`dogproject://pet/:id`、`dogproject://forum/:id`。
- 参数支持两种模式：
  - 直接 query：`?token=...&userId=...`
  - 封装 query：`?params=token%3D...%26userId%3D...`

4. 构建与发布体系
- iOS 工程接入 Pods 并固定依赖版本。
- CI 区分 `Debug/Release` 构建。
- 输出 dSYM 并接入崩溃平台。

5. 多环境注入
- `dev/staging/prod` 分离：API 地址、埋点 key、功能开关。
- RN 读取统一配置源，避免硬编码。

6. 监控体系
- JS 错误、Native 崩溃、接口失败率统一上报。
- 关键路径埋点：页面打开、接口耗时、首屏完成。

### 2.2 框架层兼容（强烈建议）

1. 设计系统对齐
- 统一颜色、字体、圆角、阴影、间距 token。
- 确保 RN 页面与 H5/iOS 视觉一致。

2. 网络与鉴权统一
- RN 复用主 App 鉴权机制：`access_token`、过期处理、401 兜底。
- 建立 refresh 机制，避免 token 双份维护。

3. 会话同步策略
- 以主 App 会话为单一真源。
- 进入 RN 页前由原生注入会话，RN 本地只做缓存与容错。

4. 原生能力抽象
- 相机、相册、定位、推送通过统一桥接层暴露给 RN。
- 避免 RN 页面直接散接多个原生 SDK。

5. 性能基线
- 指标：首屏时长、滚动 FPS、图片缓存命中率、内存峰值。
- 建立上线门槛和回归对比机制。

### 2.3 业务层改造（落地关键）

1. 页面切分策略
- 先低耦合详情页，再扩展到列表/发布页。
- 避免首批迁移登录、支付等高风险路径。

2. 参数与协议标准化
- 统一解析入口，兼容 `query` 与 `params` 两种传参。
- 对 token 中特殊字符统一 URL encode/decode。

3. 登录态兜底
- 缺少 `token/userId` 时，RN 自动触发：
  - 请求原生补齐会话，或
  - 回退到登录流程

4. 灰度与回滚
- 增加远程开关：同一路由可切换原生页/RN页。
- 支持按用户分流（白名单/比例）。

5. 测试矩阵
- 冷启动、热启动、从通知跳转、弱网、token 过期、后台恢复。
- 覆盖 iOS 多机型与不同系统版本。

## 3. 结合当前项目的落地清单

## 3.1 已完成（当前代码现状）

- `rn-app` 已建立 Expo 项目并可通过 `exp://...` 调试。
- 已支持 `pet/:id` 与 `forum/:id` 深链打开。
- 已支持 `params=` 打包参数解析。
- 论坛详情后端接口关键报错已修复（避免 500）。

## 3.2 待补齐（建议按优先级）

P0（必须先做）
1. 登录态单一真源
- 定义 iOS -> RN 注入会话协议。
- 明确 token 刷新责任归属（建议主 App）。

2. 统一路由网关
- 在前端 H5 与 iOS 原生统一生成 Deep Link。
- 统一 `forum/pet` 参数校验与兜底逻辑。

3. 线上环境 API 与安全策略
- 分离 dev/prod API base URL。
- 避免在 URL 长期透传敏感 token（可改短期 ticket）。

P1（上线前）
1. 视觉对齐
- 对齐 H5 详情页样式 token（标题、间距、阴影、按钮）。

2. 稳定性
- 增加接口超时、重试、空态、错误态 UI。

3. 观测能力
- 页面耗时、接口耗时、异常日志上报。

P2（规模化扩展）
1. 页面迁移模板化
- 沉淀可复用详情页脚手架与桥接模块。

2. 灰度平台化
- 支持动态策略下发（用户、版本、渠道维度）。

## 4. 推荐实施阶段

阶段 1：可用（1-2 天）
- 路由协议稳定
- token/userId 同步打通
- 真机可稳定打开详情页并拿到数据

阶段 2：可上线（2-4 天）
- UI 对齐 H5
- 监控埋点 + 错误兜底
- 灰度开关 + 回滚路径

阶段 3：可扩展（持续）
- 抽象通用桥接层
- 模块化迁移更多页面

## 5. 风险与规避

1. 风险：token 在 URL 透传泄露
- 规避：短效 ticket + 原生换 token；日志脱敏。

2. 风险：RN 与原生会话不一致
- 规避：主 App 为唯一真源，RN 仅缓存。

3. 风险：样式割裂影响体验
- 规避：设计 token 同源，统一组件规范。

4. 风险：首屏慢/卡顿
- 规避：图片缓存、骨架屏、按需加载、性能基线门禁。

## 6. 验收标准（Definition of Done）

- iOS 真机可从主 App 打开 RN 宠物/论坛详情页。
- 登录态一致，接口调用成功率达标。
- 异常场景（过期、弱网、空数据）均有可用兜底。
- UI 与 H5 视觉一致性达到验收标准。
- 支持灰度切换与一键回滚。
