# 多Agent协同 + 执行轨迹可解释化 PRD

## Phase 0 - 对齐与约束
一句话目标：让 AI 助手以多 Agent 协同方式执行任务，并实时展示“为什么这样做、做到了哪一步、失败如何恢复”。

范围边界：
- v1 In-Scope：Planner/Executor/Verifier 三代理协作、执行轨迹面板、步骤证据展示。
- v1 Out-of-Scope：跨租户任务编排、复杂并发图调度、自动跨系统补偿事务。

## 1. 背景与问题
当前任务执行虽有 HUD，但对外展示不足以说明“AI如何决策与验证”，对管理层与外部评审的可解释性不够。

## 2. 目标与指标
1. 引入多 Agent 协作执行框架（可观察）。
2. 提供轨迹解释面板（可审计）。
3. 提升任务执行可信度（可量化）。

指标：
1. 关键任务成功率 >= 95%。
2. 可解释轨迹覆盖率 100%（每步有 reason + action + evidence）。
3. 平均恢复时长（失败后重试成功）<= 8s。

## 3. 用户故事
1. 作为运营，我希望看到 AI 每一步为什么执行该动作，便于评审与复盘。
2. 作为产品负责人，我希望对外演示时能清晰展示 AI 的“决策-执行-校验”闭环。
3. 作为研发，我希望失败后能快速定位到具体代理与步骤。

## 4. 范围定义
### 4.1 In-Scope
1. Planner Agent：解析意图并生成执行计划。
2. Executor Agent：按计划调用工具执行。
3. Verifier Agent：结果校验与失败建议。
4. 轨迹面板：展示 step、reason、tool、result、evidence、confidence。

### 4.2 Out-of-Scope
1. 多任务并行调度图可视化。
2. 自动账务补偿与跨系统一致性事务。

## 5. 关键流程
1. 成功流：用户意图 -> Planner 产计划 -> Executor 执行 -> Verifier 校验 -> 完成。
2. 失败流：Verifier 判定失败 -> Planner 生成重试计划 -> Executor 重试 -> 校验。
3. 取消流：用户取消 -> Executor 中止 -> 轨迹记录 cancelled。

## 6. 验收标准（DoD）
1. 三代理职责清晰且日志可区分。
2. 轨迹面板每步都有 reason/action/evidence。
3. 失败后可自动生成重试建议。
4. 展示链路可用于对外 Demo。
