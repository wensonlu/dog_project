# Forum Agent Task HUD PRD

## 1. 背景与目标

### 1.1 背景
当前助手可回答与草拟，但在“执行型意图”（如“给第一个帖子点赞并评论123”）中，缺少任务可视化与稳定执行反馈。用户难以判断：
1. 助手是否真的执行了动作
2. 执行到了哪一步
3. 失败时如何恢复

### 1.2 目标
构建“对话驱动多步执行”能力：
1. 用户一句话触发多步骤操作
2. 助手浮层自动收起，切换到底部任务 HUD（Head-Up Display）
3. 实时展示任务进展、结果、失败重试
4. 基于 Web MCP 精确执行论坛动作

---

## 2. 用户故事

### 2.1 核心故事
作为论坛用户，我希望说一句“帮我给第一个帖子点赞评论123”，系统能自动完成跳转、点赞、评论，并在底部显示任务进展，让我明确知道执行成功。

### 2.2 扩展故事
1. 我可以在任务中途取消执行
2. 我可以在失败后重试某一步
3. 我可以点击“查看结果”回到目标帖子

---

## 3. 范围

### 3.1 本期（v1）范围
1. 论坛场景执行型意图：
   - 目标定位（第一个/第N个帖子）
   - 点赞
   - 评论（通过 precheck + confirm）
2. 任务 HUD 展示与交互
3. 执行步骤审计与结果校验

### 3.2 非本期范围
1. 跨模块复合任务（论坛+领养申请联动）
2. 多任务并发调度
3. 自动撤销（undo）复杂回滚

---

## 4. 交互流程

### 4.1 标准成功流
1. 用户在助手中输入：`帮我给第一个帖子点赞评论123`
2. 助手先调用 LLM Planner（`/agent/plan`）将自然语言拆解为 allowlist 工具计划
3. 前端根据计划展示“授权 AI 执行论坛互动”确认弹窗
4. 用户确认授权后，聊天浮层关闭，底部任务 HUD 出现
5. HUD 展示步骤：
   - 解析目标帖子
   - 跳转帖子详情
   - 点赞
   - 评论“123”
   - 结果校验
6. 每步状态实时更新（待执行/执行中/成功）
7. 任务完成后显示“执行完成”，可点击“查看结果”

### 4.2 失败流
1. 任一步失败，HUD 标红并展示失败原因
2. 提供按钮：
   - 重试该步
   - 终止任务
   - 查看日志

### 4.3 取消流
1. 用户点击“取消任务”
2. 任务状态变更为 `cancelled`
3. 不再执行后续步骤，HUD 保留结果摘要

---

## 5. 任务 HUD 需求

### 5.1 展示信息
1. 任务标题（如：执行论坛互动）
2. 当前步骤与总步骤（如：2/5）
3. 步骤列表（名称、状态、细节）
4. 任务按钮（取消、重试、查看结果）

### 5.2 状态定义
1. `queued`
2. `running`
3. `waiting_confirm`
4. `succeeded`
5. `failed`
6. `cancelled`

### 5.3 UI 行为
1. 执行开始自动显示 HUD
2. 执行结束 3~5 秒后自动折叠（可配置）
3. 点击 HUD 可展开详细步骤

---

## 6. 风险分级与确认

### 6.1 操作分级
1. 低风险：读取、检索、总结（可自动）
2. 中风险：跳转目标帖子、点赞、关注作者（AI 做出目标选择后必须经用户授权）
3. 高风险：发布评论、删除/封禁/置顶（评论本期包含，删除/封禁/置顶本期不包含）

### 6.2 确认机制
所有论坛执行型任务必须先走前端用户授权弹窗，授权内容包含目标、账号、动作清单与写操作提示。评论发布还必须走后端二段确认：
1. `precheck/reply`
2. `confirm/reply`

---

## 7. 验收标准（DoD）

1. 输入“帮我给第一个帖子点赞评论123”后先展示授权弹窗，确认前不发起点赞/评论请求
2. 前端必须先请求 `/agent/plan`，由 LLM Planner 产出工具 steps；固定关键词解析仅允许作为 planner 不可用时的降级
3. 用户确认后助手浮层自动收起，底部 HUD 可见并实时更新
4. 点赞与评论均成功落库
5. 失败场景可重试并恢复
6. 有完整审计日志（任务、步骤、结果）

---

## 8. 指标

1. 任务启动成功率 >= 98%
2. 任务完整成功率 >= 95%
3. 平均任务耗时 <= 4s（不含人工确认等待）
4. 用户中断率 <= 10%

---

## 9. 里程碑

### M1（1周）
1. HUD 容器 + 状态机
2. 单一任务执行链（解析→跳转→点赞→评论→校验）

### M2（第2周）
1. 失败重试
2. 任务日志展示
3. 手动确认开关
