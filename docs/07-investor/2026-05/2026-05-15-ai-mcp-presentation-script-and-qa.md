# AI MCP 汇报讲稿与领导 Q&A

## 一、逐页讲稿（10页，每页30-45秒）

### 第1页 背景与目标
我们当前项目是宠物领养平台，AI 助手已经具备知识问答 RAG 能力。
接下来我们的目标不是只让 AI“会回答”，而是让 AI“能执行”。
也就是把 AI 从信息层升级到动作层，直接参与论坛互动、商城流程和运营管理，形成可落地的业务价值。

### 第2页 节前工作总览
节前我们围绕 MCP 做了三件事。
第一是运营管理能力，第二是智能操作能力，第三是自动化测试方向探索。
前两项已经在项目里有可验证成果，第三项正在持续迭代。
整体思路是一致的：把系统能力工具化，让 AI 可调用、可校验、可治理。

### 第3页 运营管理能力
运营侧我们基于 Supabase 的 RLS 权限体系做了 MCP 工具。
核心价值是让运营同学用自然语言完成数据查询、筛选和分析，不再频繁跨系统手工拉数据。
这样可以在权限可控前提下，显著提高日常运营效率和决策响应速度。
本质上是“数据可访问”升级为“数据可决策”。

### 第4页 智能操作能力
智能操作是这次最核心的尝试。
我们没有采用截图+多模态猜点击的黑盒方式，而是将页面结构、状态和可执行动作显式暴露给 AI。
AI 通过标准 Tools 执行动作，不需要猜 UI。
这让准确性、稳定性和性能明显更接近生产要求。

### 第5页 项目落地场景
在当前项目里，我们已落地两个代表场景。
论坛场景：AI 可以按目标执行浏览、点赞、评论、关注。
商城场景：AI 可以识别下单意图，跳转订单页并进入确认流程。
同时配合任务 HUD 展示步骤状态，支持失败重试和取消，用户可感知、可控。

### 第6页 技术架构总览
架构分五层：AI 编排层、语义暴露层、Tools 执行层、后端服务层、数据层。
AI 编排层负责拆解任务；语义暴露层提供页面和动作上下文；
Tools 层承接执行；后端路由处理业务逻辑；
Supabase 提供数据和权限约束。
这是一条从意图到结果的完整执行链路。

### 第7页 执行原理（状态机）
执行机制是状态机：解析意图、定位页面、调用工具、校验结果。
每一步都有明确状态和返回值，不是“一次性黑盒调用”。
失败可以重试，任务可以取消，执行过程可视化。
因此这套机制既能保障体验，也方便工程调试与问题定位。

### 第8页 安全与治理
安全层面有三道保障。
第一是 RLS 控制数据访问边界；第二是工具白名单限制 AI 动作范围；
第三是执行日志和校验结果形成证据链。
也就是说 AI 不是任意操作系统，而是在可控边界内执行被授权的动作。
这也是它能走向生产的关键条件。

### 第9页 价值与方案对比
和纯视觉点击方案相比，我们的方案有三个优势。
第一更稳定，不依赖 UI 像素细节；第二更高效，调用工具比反复视觉推理更快；
第三更可维护，新增能力就是新增工具，不需要重训练整套策略。
因此它既适合当前业务，也适合后续规模化扩展。

### 第10页 下一步计划
下一步有三件事。
第一，完善自动化测试回归闭环，把执行和断言标准化；
第二，扩展运营工具集，覆盖看板、预警和批量操作；
第三，持续跟踪生产指标：任务成功率、平均耗时、人工替代率、异常率。
目标是把 AI 从“可用”推进到“好用、稳定、可规模化使用”。

## 二、领导高频 Q&A（10问10答）

### 1. 问：这和普通聊天机器人有什么本质区别？
答：普通聊天机器人主要做信息生成，我们这套是“可执行AI”。不仅能回答，还能在权限边界内调用工具完成真实业务动作，并且有结果校验闭环。

### 2. 问：为什么不用截图+多模态点击？
答：截图方案依赖视觉猜测，稳定性受UI变化影响大。我们采用“页面语义暴露+工具调用”，动作是结构化执行，不靠猜，准确性和可维护性更高。

### 3. 问：安全怎么保证？会不会乱操作？
答：三层控制：RLS控制数据权限、工具白名单控制动作范围、每次执行有日志和结果校验。AI只能在授权能力内执行，不能越权。

### 4. 问：目前在项目里已经落地了什么？
答：已落地论坛互动和商城链路。论坛支持目标帖子的点赞/评论/关注；商城支持智能下单意图跳转订单页，并有任务状态展示、重试、取消和校验。

### 5. 问：怎么证明它“真的执行成功”而不是只回了一句话？
答：我们是状态机执行，每一步有状态；最后必须通过后端或数据校验接口确认结果，校验通过才标记完成，不是文本层“宣称成功”。

### 6. 问：性能和体验表现如何？
答：工具化执行链路更短，推理成本比纯多模态低。我们还做了节奏控制和任务HUD，让用户既能感知进度，也能中断和重试，体验更可控。

### 7. 问：如果执行失败怎么办？
答：失败会定位到具体步骤并返回原因，用户可一键重试。因为每步可观测、可重放，排障效率高，不会像黑盒流程那样难定位。

### 8. 问：对运营团队的直接价值是什么？
答：运营可以用自然语言完成权限内数据查询与分析，减少人工拉数和跨系统切换，缩短从“发现问题”到“做决策”的时间。

### 9. 问：这套能力是否可复用到测试？
答：可以。同一机制可用于自动化回归：AI按工具执行操作，再做结果断言。相比传统脚本，对UI小改动更稳，维护成本更低。

### 10. 问：下一阶段最关键的里程碑是什么？
答：三件事：一是完善自动化回归闭环；二是扩展运营工具集（看板/预警/批量动作）；三是上线后持续跟踪成功率、耗时、异常率，验证生产价值。

## 三、30秒电梯总结（可选）
我们把 AI 助手从“会回答”升级为“能执行”。
通过 MCP 把页面语义和业务能力工具化，AI 在 RLS 权限边界内完成论坛互动、商城流程和运营查询，并通过状态机和结果校验保证可控与可追踪。
这套架构同时可复用到自动化回归测试，具备持续扩展到生产级智能工作流的基础。
